# OpenPencil Motion Adapter for Figma

This development plugin materializes the verified OpenPencil `MotionSpec` subset as native Figma
Motion tracks. It scans the current selection and reads the strict shared-plugin-data envelope at
`openpencil/motion-v1`, then delegates all native mutation and readback to the single
`@open-pencil/fig` transaction also embedded by generated adapter scripts.

The shared envelope is an interoperability mirror, **not** a native Figma timeline. Opening an
exported file in Figma does not materialize Motion until this plugin (or a generated adapter script)
successfully applies that envelope. A `cleared` envelope is only a tombstone preventing future
application; it never grants permission to delete native tracks already present in Figma.

## Verified subset

The adapter currently accepts exactly one `mount` track with zero delay, one iteration, `normal`
direction, `both` fill, and no exit animation. It writes only `opacity`, `x`, `y`, `rotate`,
`scaleX`, and `scaleY` as manual property tracks, using standard or cubic-bezier easing. Unsupported
triggers, delays, iteration/direction/fill semantics, exit behavior, duplicate lowered timestamps,
and other channels fail closed before any Figma mutation.

## Safety contract

- The conflict policy is always `replace-owned`.
- Animation styles, foreign property tracks, and indexed paint/stroke/effect tracks are never
  removed.
- Invalid ownership records and Figma-edited owned tracks fail closed.
- Every mutation starts from a `commitUndo()` boundary, verifies native track, timeline, and
  ownership readback, and calls `triggerUndo()` after a partial failure. `rolledBack: true` is
  reported only when a post-undo fingerprint matches the preflight state.
- Existing timelines are never shortened. Timeline growth is disabled by the plugin entry point;
  the shared applicator exposes an explicit `allowTimelineGrowth` option for controlled callers.
- The plugin makes no network requests.

Each selected node produces a structured `applied`, `unchanged`, `skipped`, `unsupported`,
`conflict`, or `failed` result. The complete summary is written to the Figma developer console and
the aggregate is shown when the plugin closes.

## Build and test

From this package directory:

```sh
bun run check
```

Or run the gates separately:

```sh
bun run typecheck
bun run test
bun run build
```

The build creates the ignored local artifact `dist/code.js`. In Figma Desktop, choose **Plugins →
Development → Import plugin from manifest…** and select this package's `manifest.json` after the
build finishes.

The checked-in manifest ID is a local-development placeholder. Replace it with the ID generated by
Figma before publishing or when your Figma development setup requires an assigned ID.

## Compatibility boundary

The source is checked against installed official `@figma/plugin-typings` `1.131.0`. Figma still marks the
Motion Plugin API as Beta, so an API change may require an adapter update even though the shared
OpenPencil envelope remains stable. The relevant official references are:

- [Motion API overview](https://developers.figma.com/docs/plugins/api/Motion/)
- [`applyManualKeyframeTrack`](https://developers.figma.com/docs/plugins/api/properties/nodes-applymanualkeyframetrack/)
- [Plugin API Update 130](https://developers.figma.com/docs/plugins/updates/#version-1-update-130)

The automated suite verifies the official typings and isolated API-compatible test doubles. A real
Figma Desktop apply/readback/undo ACK is still pending and must not be inferred from those tests.
