# Shader host contract

Shader paints remain image fills/strokes plus validated plugin data. Legacy entries omit `input`. A content filter adds `input: { kind: 'self', version: 1 }`; its frame also records a content signature. Only this data and encoded image bytes persist. Canvas, bitmap, device and texture handles stay in the host.

`setContentShader` appends a paint, preserving the source fills and hierarchy in one undo step. The static support predicate is shared by authoring, the renderer and exporters. If later edits introduce unsupported runtime content, projection returns the authored subtree, excluding the content paint. It never turns a control into an image. `generatedEffect` and the Motion/Lowcode contracts are independent and unchanged.

Supported node types are RECTANGLE, ELLIPSE, TEXT, FRAME and GROUP, including static image paints and supported descendants. Masks, non-NORMAL blend modes, nested content filters, controls, bindings, variables, Motion and generated effects are outside this first-stage sampling contract. Capture stays inside the root's rectangular box, including when authored children extend beyond it.

For a single selected layer, the inspector offers Pixelate, Twirl and Saturation with the library's native parameter units and bounds. Pixelate's density is the number of pixels along the longest edge (higher values make smaller blocks); Twirl uses intensity from -5 to 5, and Saturation from 0 to 3, where 1 preserves color and reset uses 0. Custom stacks or extra parameters stay custom until the user explicitly selects a shortcut. Reset and parameter edits use the existing Shader paint command and undo history. `canSetContentShader` also rejects overlapping parent/child selections before any edit.

The editor reuses `extractExportGraph` and the existing raster compositor to capture a private node-local subtree. It removes the content Shader, resets only the root transform/opacity, and clips capture to its rectangular box. No backdrop is sampled. The compositor's isolated document caches keep the capture apart from live images and retained pictures. Captures are capped at 1024 pixels per side; static output uses `shaderFramePixels` (2048 maximum). The temporary native surfaces are released by the raster exporter. `captureShaderContent(id, signal)` returns ephemeral source bytes and their content signature, without publishing a static output; graph replacement, cancellation or a changed source invalidates the result.

During preview, supported own-content filters use that capture through the existing player and live-image/frame bus. Time-based effects animate over a static source, and source/preset/size edits replace the texture; unchanged frames reuse it. Input initialization is serial, bounded to 10 seconds, and limited to four visible own-content players with a 1024-pixel longest edge. Extra layers keep their saved image, and moving a content layer offscreen releases its player. Local layer dimensions determine texture aspect even when the layer is rotated. A usable saved frame is required before own-content playback starts. The original procedural fills and strokes keep their existing playback behavior.

DOM preview islands consume the same player frames through `IslandShader`. The preview host wraps the projected own-content image with its saved image and an inert canvas; this decoration has `pointer-events: none`. Behaviour controls remain real Reka components, with browser focus and input handling. This wrapper belongs only to the preview host: ordinary component and Lowcode exports continue to emit the static image, without an own-content Shader runtime. Runtime controls, bindings and Motion sources remain outside the sampling predicate.

The locked dependency is `shaders@4.0.4`. The host injects a transient `ImageTexture` containing a blob URL of the captured PNG, nested inside the selected filter components. It uses `onNaturalSizeChange` and `getNaturalSize` to await the library's source decode/upload before keeping a frame. The wait is cancellable and bounded by the static job's deadline. The native media shader performs sRGB decoding and owns its GPU texture; renderer disposal and URL revocation release the host resources. Document presets contain neither that URL nor the injected texture node. Static draws also check WebGPU validation scopes, since a broken composition may otherwise resolve without a global failure reason. Vite keeps the Shader entrypoints out of dependency optimization: the adapter-backed browser regression otherwise produces omitted TypeGPU expressions and invalid textures.

Still frames keep transparent PNG / opaque JPEG encoding. Playback checks `getFailureReason()` after initialization and every frame and subscribes to `setOnUnavailable()`. An unavailable player stops publication, removes the live image, notifies DOM islands to clear their overlay and restores the saved image. Failed preset/content keys are not retried every animation frame. Initializers that finish after stop, deletion, document replacement or an obsolete source edit dispose their renderer, texture subscription and blob URL and cannot publish. Pending frame waits are also cancelled on stop, so a late driver does not block resource retirement or another document. Live frames never replace the document's encoded fallback; save and export still settle their own static jobs.

Static drawing uses a serial queue with a 10-second operation bound, graph identity and preset/size/content checks. Editing during a draw queues the replacement and invalidates the obsolete result. `settleShaderFrames` waits for both queued and active work; targeted calls schedule only stale frames within their requested subtrees. Failed keys retain saved bytes and are not retried by every export. New edits or a new rasterizer allow another attempt. Cancellation and graph replacement release waiters; late work cannot write into another graph.

`getShaderFrameStatus(nodeId, image)` distinguishes queued, rendering, current, saved fallback, missing and unsupported frames. Its reason identifies unavailable rendering, failure, timeout or a stale saved frame. Static and playback failures publish `shader:status-changed` without writing host state into plugin data or undo history. `retryShaderFrames(nodeIds)` clears only those layers' failed attempts and requests another static draw and, during preview, playback attempt; it does not retry in a loop. The inspector shows this status for visible Shader fills and strokes on a single selected layer. Without a host renderer, it offers no ineffective retry action. A saved fallback can be older than the edit; a missing frame is never presented as successful generation.

Live hosts report `starting`, `playing`, `offscreen` or `limited` through `reportShaderPlaybackState`; the optional `playback` field is separate from static-frame readiness. Reports are scoped to the preset and source frame, and stop, failure, document replacement and host disposal clear them. Notifications occur on transitions or source revisions, not on every animation frame. The inspector shows these states, and canvas-only preview displays a noninteractive badge with layer counts while the panels are hidden. Its four-layer limit refers to own-content players; static saving and exports continue to use the latest available still frame.

Rebuilding the static host does not clear a playback failure: only an explicit retry or `reportShaderPlaybackReady` after a successful live draw clears it. Obsolete static jobs are aborted as soon as their paint, source content or layer is removed or changed, so settlement does not wait for a hung old renderer before drawing the current edit.

Copied subtrees can initially share their saved bytes. Before rendering a content filter whose image key is shared, the host gives it an independent output key and retains the saved fallback, so editing a copy cannot overwrite its source's frame.

Imported FIG images use canonical SHA-1 names. A successful Shader redraw keeps those immutable bytes and publishes under a fresh runtime image name, remapping the paint and its metadata together. Failed draws keep the original name and saved bytes. This prevents an incremental FIG save from aliasing retained archive entries to new pixels; the strict image-alias reader remains unchanged. Both procedural and own-content paints use this publishing rule.

The browser and Tauri document save/export actions await settlement before serializing. HTML, SVG, ordinary React/Vue components and Lowcode compiler projection consume the content image, preserving unrelated controls and bindings. Content components emit no `shaders` dependency. Existing procedural component exports retain their Shader runtime. Headless IO/compiler paths consume saved bytes; missing required frames fail explicitly. Editing sources and saving a document without a GPU can preserve an unrendered preset, but that is not successful static frame generation. External Figma does not execute OpenPencil content filters; native `.fig` round trips preserve the editable sources and extension metadata.

## Verification boundaries

Unit rasterizer doubles exercise queue/lifecycle contracts; CanvasKit CPU pixels exercise compositing and capture, not WebGPU. Browser tests label simulated renderers separately from adapter-backed rendering. The real WebGPU case skips explicitly if no adapter exists. Playwright Chromium/WebKit, native Tauri/WebView, external Figma and physical Safari tabs are distinct acceptance targets. A mock, build or CPU snapshot cannot establish any of those runtime results.

`live-lifecycle.spec.ts` uses simulated renderers to check late captures, late initialization, pending-frame cancellation, failure, explicit retry, deletion, document switching, undo/redo, unsupported bindings and resource limits. `live.spec.ts` separately checks actual WebGPU animation, source refresh, rotated sizing, unchanged saved bytes and committed canvas snapshots; `live-island.spec.ts` checks actual animated DOM decoration and input focus. `tests/e2e/native/shader-playback.spec.ts` is the separate real-WebView pixel test and skips explicitly without an adapter. These tests do not simulate hardware device removal or establish Windows/Linux acceptance.

On 2026-10-23, Chromium passes the own-content playback pixels, source refresh and DOM input-focus checks. The macOS native-test WebView also passes actual animated island pixels, edited source refresh and unchanged saved fallback bytes; the same run passes both GPU and deliberately disabled-GPU native file/PNG paths, ordinary text input, support facts and protected-path refusals (eight checks, no skips). Native startup diagnostics still mention the optional external `tauri-driver`; these checks execute through the configured embedded driver with real WebView sessions. This does not establish a signed release, hardware-loss recovery or other native platforms.

A targeted follow-up on the same date passes four native checks across three specs: live island pixels and focused-menu selection, image/text/container sampling with consecutive edit/save/reopen, actual WebGPU file/PNG output, and deliberately disabled-GPU saved-frame fallback. Each sample's PNG region contains visible pixels. The 32 focused Core checks use simulated output frames and CanvasKit input capture; they separately cover immutable canonical image names and the second FIG roundtrip. These are limited regressions, not a full suite or pressure run.

Actual Safari UI acceptance imports those three sample kinds, edits Twirl intensity and immediately downloads the FIG, previews live output, returns to static output and exports a visually checked 560 × 180 PNG. Reading the edited download through Core IO exposes the former alias collision and succeeds after the publishing fix. A packaged macOS native-test app separately verifies button state changes, input-to-text binding, opening/selecting a native dropdown, and actual OS typing beside a live Shader. Native Select All now follows the focused shadow input or the authenticated compiler-preview channel; React/Vue channel regressions also check Select All, Undo, Redo and rejection of wrong-channel or extra-field messages. This uses the existing isolated preview transport and does not add a runtime to ordinary component exports. The embedded driver's shadow-host keyboard limitation is not evidence of OS input delivery; the actual OS check is separate.

`tests/e2e/canvas/shader/persistence.spec.ts` edits parameters and size immediately before the product's download-save action, reopens the downloaded FIG, exports a PNG, and reopens the saved document in both missing-WebGPU and missing-adapter environments. `tests/e2e/native/shaders.spec.ts` separately exercises native file writes and reopen: its `webgpu` case requires an adapter, while `saved-fixture` deliberately disables the host and uses a known PNG to test fallback. Run native checks against the isolated `native-test` binary; a browser save pass does not establish native file I/O acceptance.

`tests/e2e/canvas/shader/fallback.webkit.spec.ts` runs actual WebKit downloads, FIG reopen and PNG export with WebGPU disabled and a known saved PNG. It checks fallback retention and nonempty export, and does not claim WebGPU generation. The Chromium filter controls test renders the installed filters through WebGPU and keeps canvas snapshots; its failure/retry companion uses explicitly simulated frame results.

The macOS native-test build on 2026-10-22 opens the editor and passes seven checks: support/engine facts, ordinary WebView text input, actual WebGPU Shader save/reopen and PNG output, explicitly disabled-WebGPU saved-frame fallback, and filesystem permission refusals. Native FIG loading can remap layer IDs; the tests resolve the reopened layer in the current document and isolate each fixture. GPU-free reopening disables WebGPU for the load and restores that capability afterwards; the saved frame must remain byte-identical. Exported PNGs have the expected dimensions and colored pixels, not just a valid header.

The previous native startup abort came from the existing Unicode JSON validators with bounds 16384 and 32768 exceeding Rust regex's default 10 MiB compiled-size limit. The locked Shell 2.3.5 runtime now has a documented local patch with a bounded 32 MiB compiler budget and error propagation. Its capability patterns, command names, fixed arguments and argument-length limits are unchanged. Rust tests compile every configured validator and exercise Unicode, length boundaries, controls and malformed patterns.

A separately packaged native-test application also opens the test FIG through the real macOS file dialog, shows the ready Shader state, and exports a visually checked 140 × 90 PNG through the system save dialog. Cancelling another save returns to the editor without creating a file. This local application uses ad-hoc signing; it is not a signed or notarized release acceptance.

Safari 26.6.2 also passes a manual two-document smoke check in a private window: 20 observed switches retain the ready Shader frame and an independent rectangle, with both canvases visually checked. This does not exercise forced WebGL context loss or hardware GPU loss. Larger context-pressure runs, Windows and Linux remain unverified.
